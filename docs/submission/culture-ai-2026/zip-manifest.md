# 제출 ZIP 구성안

작업 시각:

```text
NOW=2026-06-26 09:30 KST
NOW_DATE=2026-06-26
WINDOW_START=2026-03-28
```

최종 트랙 판정: **DOWNGRADE: ADX 아이디어**

공식 페이지 기준으로 신청 서류는 양식에 맞춰 작성한 뒤 PDF로 변환하고, 1개 압축파일로 제출해야 합니다. 접수 화면 기준 압축폴더명은 `분야_부문_팀명.zip` 형식이며, 파일은 10MB 이내로 맞춥니다. 공식 페이지에서 마감 시각은 확인하지 못했으므로 제출 문서에는 마감 날짜만 씁니다.

## ZIP 파일명

권장 파일명:

```text
신기술활용_ADX아이디어_Heznpc.zip
```

주의:

- 외부 제출 표기는 `Heznpc`만 사용합니다.
- 공식 양식 zip 안에서 요구하는 개별 파일명이 있다면 그 파일명을 우선 유지합니다.
- 접수 후 파일 수정이 불가하므로 업로드 전 최종본만 압축합니다.

|---|---|---:|---|---|

## ZIP에 넣지 않는 편이 안전한 파일

| 파일/정보 | 이유 |
|---|---|
| 원본 전체 로그 파일 | 로컬 절대 경로나 개발 환경 정보가 포함될 수 있으므로 외부 제출에는 요약 PDF가 안전합니다. |
| `.env`, API key, 토큰, 계정 식별자 | 보안 및 개인정보 리스크가 있습니다. |
| 실명, 이메일, 외부 개인 이름이 포함된 문서 | 외부 제출 표기는 `Heznpc`만 사용합니다. |
| 앱 전체 소스 압축본 | 공식 양식에서 요구하지 않는 한 용량 초과와 불필요한 정보 노출 위험이 있습니다. |
| 핵심 플로우가 아닌 스크린샷 다량 | 현재 스크린샷은 알림 권한 팝업 수준이므로 우수사례 증빙처럼 보이지 않게 요약합니다. |

## 10MB 제한 체크

압축 전 확인 명령:

```bash
du -sh 신기술활용_ADX아이디어_Heznpc.zip
```

10MB 초과 시 우선순위:

1. 보조 증빙 PDF의 이미지 해상도를 낮춥니다.
2. 원본 로그 전문 대신 핵심 출력 요약만 남깁니다.
3. 스크린샷은 1~2장만 포함합니다.
4. Markdown 원본과 소스 코드는 제외합니다.

## 제출 전 파일명 예시

```text
신기술활용_ADX아이디어_Heznpc.zip
├── 01_참가신청서_Heznpc.pdf
├── 02_참가서약서_Heznpc.pdf
├── 03_개인정보수집이용동의서_Heznpc.pdf
├── 04_기획서_dol-pin_Heznpc.pdf
└── 05_보조증빙_dol-pin_Heznpc.pdf  # 공식 업로드가 추가 자료를 허용하는 경우만
```

주의: 공식 다운로드 양식의 원래 파일명 유지 요구가 있으면 위 예시는 공식 양식 파일명에 맞춰 조정합니다.
